Press Play to decode the same clip in every decoder at once.
A demo, not a benchmark. Every decoder runs at once on this machine and they contend for cores, cache and memory bandwidth, so these figures move with system load. Published numbers come from tools/bench/codec-bench.ps1 — one arm at a time, pinned to one core at High priority, ABBA-interleaved, 21 pairs, paired win rate with a z-score, work parity checked.

The clip plays at its own frame rate, so every pane shows the same picture at the same moment and the run lasts as long as the video does. Speed therefore cannot be read off the clock — it is measured as CPU time, sampled from each decoder process, which accrues only while that process is actually running. A decoder that spends 3 s of CPU delivering 20 s of video is running at 6.7× real time. Timing read() instead was tried and inverted the answer: with the reader paced the decoder fills the pipe, so it measured buffering rather than decoding.

What a table cannot show, and this can: every decoder emitting the same pixels. Each frame is hashed as it arrives and compared across all arms — so the scalar reference, the AVX2 kernels and ffmpeg agreeing is visible rather than asserted.
